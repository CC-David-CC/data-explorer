# Data Explorer optional lifecycle research

Based on a384e55a9; no deployment. The lifecycle reports dirty SQL/view changes and blocks quiescence during data loading, selection, queries, chart changes initiated by app actions, project/results saves and exports. It makes the app inert during a lease. Perspective configuration events can arrive asynchronously and still advance revision while paused, allowing the host to detect a late change. Existing query rollback, source/version conflict checks and asynchronous worker cleanup remain in place. Disposal closes the lifecycle idempotently.

Run `node --test tests/data-explorer-lifecycle-reference.test.mjs`. Build an isolated data-explorer catalog, run `tests/jsketcher-preview-csp.py --isolated`, and run `tests/data-explorer-lifecycle-session-review.test.mjs` against the loopback CODI_TEST_URL and dedicated Chromium CODI_TEST_CDP. The signed-account desktop test exercises cancellation with SQL edits, changes during confirmation, a real query held at the viewer boundary, a held project save with server verification, real Perspective chart restoration during pause, failed logout, account separation and termination of the tracked DuckDB worker. The first query-hold harness assigned to a proxied viewer method and timed out; defining a configurable own property corrected the harness. The run did not verify every Perspective internal worker, simultaneous Data Explorer windows, phone layout, physical touch or interrupted CSV safety-worker cleanup.
